## Decision frozen by S4

`proot-distro 5.6.0` publishes `rootfs/` before acquisition or extraction,
so an observable alias after a crash is attributable but may be incomplete.
Termux Stacks must never start or reuse it.

- `owned`: a durable unique intent, proven containment, a drained exact child
  scope, and positive public observations attribute the alias. Exact removal
  is permitted; a retry uses a new alias.
- `ambiguous`: any lost identity, inconsistent observation, negative public
  inventory after invocation may have begun, or failed cleanup. Preserve the
  artifact and require diagnosis; do not remove, retry, or start it.
- `absent`: requires durable phase ordering that proves the engine invocation
  could not have begun. Negative `list` output alone is never sufficient.

## Limits

S4 is a black-box qualification of `proot-distro 5.6.0` on one aarch64
Termux/Android device. F2 proves the interval after the public layer marker
and before any later public phase marker; it does not claim visibility into
the engine's internal extraction instruction. The run used only synthetic
app-private prefixes and disposable aliases.

S4 does not implement or qualify SQLite operations, daemon crash recovery,
production parsing, rootfs registration, workload lifecycle, duplicate
prevention, updates, rollback, garbage collection, or multi-service behavior.
Those begin with the S5 vertical slice.
