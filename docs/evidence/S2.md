dichiarazione di build riproducibile fra versioni Podman.

## Risultati

| Caso | Oracolo indipendente | Registry | Esito |
|---|---|---|---|
| T1 sessione singola | viva, poi exit 0 | presente, poi potato | PASS |
| T2 stesso alias | due child distinti | due righe, rimozione indipendente | PASS |
| F1 write denied | child vivo | PID omesso, exit `ps` 0 | PASS |
| F2 read denied | child vivo | PID scompare e ricompare dopo restore | PASS |
| F3 JSON troncato | child e lock vivi | PID omesso; file potato dopo exit | PASS |

F1 prova il fallimento silenzioso della registrazione. F2 prova che un errore
di lettura può essere indistinguibile da registry vuoto. F3 prova che anche un
record ancora locked può essere escluso perché malformed. I fault hanno
toccato soltanto la directory `sessions` del prefix sintetico; mode e inode
sono stati verificati prima delle asserzioni.

## Decisione architetturale

`proot-distro ps --quiet` positivo è evidenza complementare, ma output vuoto
con exit 0 non è mai prova sufficiente di assenza. Durante la vita dello
stesso demone, il child handle con boot ID, PID e `/proc` start time è
l'evidenza primaria. Dopo la perdita di quell'handle, empty, errore o record
malformed producono `unknown`: v0 non esegue restart, recreate o delete
automatici.

S2 non qualifica parent/daemon loss, root PRoot ucciso con guest vivo,
propagazione TERM o tree-kill; questi casi passano a S3. Non qualifica inoltre
ownership durante `install`, che resta S4.
