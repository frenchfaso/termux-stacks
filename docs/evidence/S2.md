## Results

| Case | Independent oracle | Registry | Result |
|---|---|---|---|
| T1 single session | alive, then exits 0 | present, then pruned | PASS |
| T2 same alias | two distinct children | two rows, removed independently | PASS |
| F1 write denied | child alive | PID omitted, `ps` exits 0 | PASS |
| F2 read denied | child alive | PID disappears and returns after restore | PASS |
| F3 truncated JSON | child and lock alive | PID omitted; file pruned after exit | PASS |

F1 proves that registration can fail silently. F2 proves that a read error can
be indistinguishable from an empty registry. F3 proves that even a still-locked
record can be excluded because it is malformed. The faults touched only the
synthetic prefix's `sessions` directory; its mode and inode were verified
before the assertions.

## Architectural decision

Positive `proot-distro ps --quiet` output is complementary evidence, but empty
output with exit code 0 is never sufficient proof of absence. During the
lifetime of the same daemon, the child handle with boot ID, PID, and
`/proc` start time is the primary evidence. After that handle is lost, empty
output, an error, or a malformed record produce `unknown`: v0 does not restart,
recreate, or delete automatically.

S2 does not qualify a killed PRoot root with a live guest, TERM propagation, or
tree-kill behavior; those cases move to S3. It also does not qualify ownership
during `install`, which remains S4, or real-daemon loss and reconciliation,
which remain S5.
