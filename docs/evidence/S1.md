environment as hexadecimal to avoid quoting and locale ambiguity.

The bundle also records the hashes of all four Dockerfiles. The command cases
demonstrated:

| Image shape | Without override | With arguments after `--` |
|---|---|---|
| Entrypoint + Cmd | concatenates Entrypoint and Cmd | preserves Entrypoint, replaces Cmd |
| Cmd only | runs Cmd | runs the entire override |
| Entrypoint only | runs Entrypoint | concatenates Entrypoint and override |
| neither | exits with error 1 | runs the entire override |

A trailing separator without arguments, `run ALIAS --`, is equivalent to no
override for both Entrypoint+Cmd and the image without a command. Therefore,
v0.1 rejects `command: []` and always distinguishes an absent field from a
present, non-empty array.

The run also verified:

- literal arguments containing spaces, a non-leading empty string, `$HOME`,
  `*`, a semicolon, and a `--` prefix;
- overriding and adding ordinary non-reserved environment variables, without
  a shell;
- OCI WorkingDir and a separate engine override;
- propagation of exit status 23;
- `run --get-proot-cmd` with a direct command;
- `login -- COMMAND` through `/bin/sh -c`, and therefore excluded from the
  runtime path.

Random `txs-s1-*` tags and aliases were recorded before creation and removed
only by exact name. At the end, the public inventories returned to their
baseline: container `alpine-proot` and image `alpine:3.24.1`. This proves
cleanup of observable objects, not byte-for-byte identity of the engine cache
or ownership/recovery; those remain in scope for S2–S4.
